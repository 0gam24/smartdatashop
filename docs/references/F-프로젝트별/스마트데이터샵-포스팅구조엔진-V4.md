## 0. 왜 만들었나 (배경 진단)

2026-08-26 기준 최근 발행 펄스 10편의 문서 골격이 **10/10 동일**했다:

- 고정 슬롯 시퀀스: [정의 → 요건 → 금액 → 변경 → 체크리스트 → 유형별 표 → 큰 그림 → FAQ]
- FAQ 정확히 3개(10/10), Q1 = "X는 무엇인가요?" 정의형(29/30)
- 체크리스트성 블록 글당 2개, FAQ에 본문에 없는 신규 정보 0건
- "큰 그림" 마무리 섹션 = 본문 재요약

2026-07-10 문체 변주 룰은 **문장 표면**만 다양화했고 **문서 구조**는 단일 템플릿으로 남았다. 구글의 scaled content abuse(AI 대량 생성) 판정은 문장이 아니라 이 구조 반복을 본다. 따라서 주제·키워드 선정 운영은 그대로 두고, **본문 구조를 검색의도에 따라 글마다 다르게** 만드는 것이 본 규약의 전부다.

콘텐츠 우선순위 체인 (V4.0 원문):
검색의도 > 사실 정확성 > 1차 출처 > Information Gain > 독창적 가치 > 실제 데이터 > 맥락과 해석 > 예외·마찰 지점 > 자연스러운 전문성 > 가독성 > 기술 SEO.

## 1. 구조 선택 — 검색의도별 TYPE (모든 글 동일 템플릿 금지)

작성 전 이 글의 PRIMARY INTENT(핵심 검색 질문)를 정하고 TYPE을 고른다 (조합 가능):

| TYPE | 성격 | 자연 골격 예 (강제 아님) |
|---|---|---|
| A | 문제해결형 | 증상 → 원인 → 해결 경로 → 예외 |
| B | 제도설명형 | 핵심 조건 → 대상 → 금액 → 신청 → 예외 → 실무 마찰 |
| C | 비교분석형 | 핵심 차이 → 비교표 → 항목별 분석 → 상황별 판단 |
| D | 계산형 | 기준 → 산식 → 사례 → 결과 해석 |
| E | 사례분석형 | 사례 → 구조 분해 → 일반화 조건 |
| F | 변경사항형 | 무엇이 달라졌나 → 이전과 차이 → 적용 시점 → 영향받는 조건 |
| G | 산업·기업 심층형 | 산업 배경 → 구조 → 데이터 → 리스크 → 판단 기준 |
| H | 투자테마형 | 테마 배경 → 기업별 연결 검증 → 하드 데이터 → 리스크 → 판단 기준 |

- H2는 실제 질문을 해결하는 것만. 개수 채우기 섹션 금지, H2 개수 하한 없음.
- H2 골격이 기존 발행 글과 겹치지 않게 재구성한다. 자동 검출은 백스톱일 뿐이다(§9) — **골격 다양화의 실질 책임은 작성자**.
- 도입 첫 화면: 검색자가 가장 궁금한 답(핵심 수치·조건·판단 기준)부터. "이 글에서는 ~을 정리한다" 류 고정 도입 문형 반복 금지.
- 각 H2 첫 문단 = 그 섹션의 즉답 (AEO, 유지).
- 인용 단락(`> 원문` + `[^N]`)과 footnote 자연 분포는 기존 ADR 0006 룰 그대로.

## 2. Information Gain — 독창적 가치 2개 이상 의무

단순 "1차 출처 재구성 요약"은 발행 금지. 아래 메뉴에서 주제에 맞는 것을 **2개 이상** 확보한다 (기존 페르소나 매트릭스·국제 비교·표 1개 일률 의무는 폐지 — 전부 선택지로 전환):

① 직접 계산("편집자 계산: 식" 명시) ② 기존 문서에 없는 비교 기준 ③ 공개 사실 기반 독립 해석 ④ 명확한 기준의 분류 ⑤ 시간 흐름 타임라인 ⑥ 독자 판단 기준 제공 ⑦ 조건별 시나리오 ⑧ 실무 마찰 지점 분석 ⑨ 교차 출처 종합 ⑩ 수치의 의미 해석 ⑪ 검색 결과에 없는 후속 질문 답변 ⑫ 페르소나별 영향

- 정보가 부족하면 분량을 늘리지 말고 **리서치를 추가**한다. 그래도 못 채우면 그날 편수를 줄인다(발행 보류).
- "상황에 따라 다르다" / "공식 홈페이지를 확인하라"를 정보 대체물로 쓰지 않는다 — 쓸 경우 구체적 확인 경로·실데이터 동반.
- 표는 비교·데이터 구조화가 필요할 때만 (의무 아님).

## 3. FACT / INTERPRETATION / ESTIMATION / EXAMPLE 구분

| 구분 | 정의 | 표기 |
|---|---|---|
| FACT | 검증 가능한 사실 | ADR 0006 4기준 (footnote 페어링·발표일 명시·deep link·검증불가 격리) |
| INTERPRETATION | 사실 기반 독립 분석 | "편집자 해석:" 라벨 |
| ESTIMATION | 명시된 가정 기반 추정 | "편집자 추정(가정: ~):" 라벨 |
| EXAMPLE | 이해용 가상 사례 | "가상 사례" 명시 |

- 추정을 사실처럼, 가상 사례를 실경험처럼 쓰지 않는다. 1인칭 경험("직접 해보니/신청해보니") 절대 금지.
- 라벨링된 해석·추정 레이어는 Information Gain의 핵심 — 위축시키지 말 것. 단 FACT 검증은 불변.

## 4. 중복 제거 엔진 (scaled content 신호 차단 핵심)

- **체크리스트성 블록**(체크리스트/체크포인트/확인 포인트/확인사항/점검/핵심 정리) **문서 전체 최대 1개.**
- **FAQ는 조건부** — 본문이 답하지 않은 실제 후속 질문·예외·경계 조건·흔한 오해만. 본문 재서술 Q&A 금지. **새 정보가 없으면 FAQ 섹션 삭제.** "Q1. X는 무엇인가요?" 고정 정의 문형 금지(정의는 tldr·도입 담당). 매 글 3개 고정 금지.
- **마무리 섹션 = 본문 재요약 금지.** "~가 주는 큰 그림" 류 재요약 슬롯 폐기. 마무리는 독자의 다음 행동: 무엇을 추가 확인할지, 어떤 공식 자료(고시·통계 DB·DART)를 볼지, 어떤 조건에서 판단이 달라지는지. 1~2문단이면 충분.
- **표 직후 해설 = 표에 없는 함의·판단만.** 표 행 수치의 산문 재나열 금지.
- 동일 핵심 수치를 제목 → tldr → 도입 → 본문 → 표 → FAQ에 5~7회 반복하는 구 패턴 금지.
- **문단 삭제 테스트**: 삭제해도 독자가 새 정보를 잃지 않는 문단은 삭제·통합.

## 5. 표현 룰 (AI 문체 티 제거 룰의 구조 확장)

- 산문 "→" 화살표 단계형 표현 **글 전체 최대 1회** (표 셀 0회, 각주 서지·코드 예외).
- 습관 표현 금지: "첫째,/둘째,/셋째," 열거, "결론적으로", "정리하면,", "다시 말해", "쉽게 말하면", "표에서 보듯", "표를 풀어 보면".
- 전각 대시(—) 제목·tldr·본문 산문 금지 + 고정 보일러플레이트 변주 의무 (2026-07-10 룰 유지).

## 6. 분량 — 패딩 금지 원칙

- 공백 제외 3,000자 이상 유지 (AdSense 재건 정책) — 단 **중복 없는 3,000자**.
- "자수 미달 시 배경·시사점 보강" 류 패딩 지시 폐기. 미달 시 리서치 추가, 그래도 부족하면 발행 보류(편수 축소가 정답).

## 7. 메타 (목표 밴드)

- title: 목표 30~40자 (Zod 상한 60자), 핵심 키워드 앞배치. 본문에 없는 약속·과장(무조건/100%/폭등) 금지.
- tldr(meta description 역할): 목표 90~150자 (Zod 상한 200자). "X는 Y다" 정의 문장 포함(LLM 인용), 키워드 반복 금지.

## 8. 금융·관련주 콘텐츠 추가 룰

- 관련주 언급 시 기업별 연결 근거 4단계 명시: **[직접 관련] / [간접 관련] / [시장 테마상 연관] / [관련성 낮음]**. "테마 포함 = 수혜 확정" 논리 금지.
- 하드 데이터(매출·영업이익·관련 사업 매출 비중·수주잔고·CAPA·현금흐름 등) 1개 이상 분석 없이 종목 나열 금지.
- 리스크 병기 의무: 과열·실적 괴리·낮은 매출 비중·CB/BW 희석·유상증자·고객 집중 등.
- 수익 보장·상승 확정·목표주가 생성 절대 금지 (확인 불가 공시번호·전망치 포함).

## 8b. 상단 리드 차트 의무 (2026-08-26 운영자 지시)

매 신규 글 본문 최상단에 데이터 차트 1장. frontmatter `chart`(type bar|line / title ≤32자 / unit / source / **alt=대표 키워드 필수** / series 2~6개·라벨 ≤12자·값 소수 2자리·bar 음수 금지)만 작성하면 빌드가 하우스 스타일 WebP(1200×675, FT/Reuters 미니멀 — paper 배경·단일 강조색·값 직접 표기·자료 출처 포함)를 자동 생성해 삽입하고 NewsArticle LD·이미지 사이트맵에 등록한다.

- series 값은 본문 footnote 페어링된 검증 수치만 (fabrication 0)
- 차트화할 수치가 정말 없는 글만 생략 가능 — 억지 차트는 AI 티
- 디자인은 코드 고정(`src/lib/og/lead-chart.ts`) — 작성자는 데이터만 채운다
- 게이트: verify:structure 가 수치 글(수치 토큰 3+)의 차트 누락을 fail 처리

## 9. 자동 게이트 — verify:structure

`scripts/verify-post-structure.mjs` 가 pulse·insight 컬렉션의 **2026-08-27 이후 발행분**을 검사한다. 기발행 글은 소급 수정 금지(색인 보존)로 검사 제외.

| 급 | 검사 항목 |
|---|---|
| FAIL (차단) | 체크리스트성 블록 2개+, 산문 "→" 2회+, 산문·제목·tldr 전각 대시, FAQ 고정 정의 문형, 표 재서술 개시 문형, "첫째,+둘째," 열거, H2 시퀀스 완전 복제, 비종결 코드 펜스, 수치 글의 상단 차트 누락 |
| WARN (신호) | H2 슬롯 시퀀스 유사, FAQ 정확히 3개, "큰 그림" 헤딩, title 40자+, tldr 밴드 이탈, 습관 표현, 3,000자 미만 |

- 편입 지점: `verify` / `verify:strict` 체인 선두 + build-check CI(모든 PR) + writer.mjs 자동 발행 직전 인라인 검사(날짜 무관 상시).
- 게이트는 백스톱이다 — 통과가 "구조 다양화 충분"을 뜻하지 않는다. 발행 전 직전 5편의 H2 골격과 눈으로 대조한다.

## 10. LD 자동 발행과의 관계

FAQPage/HowTo JSON-LD는 해당 블록이 *실제 가치가 있어 존재할 때만* 자동 발행되면 충분하다. **LD 트리거를 위해 FAQ·체크리스트를 억지로 넣지 않는다** — 실제 페이지와 불일치하는 가짜 구조가 더 위험하다. 참고: Google은 FAQPage 리치 결과를 2026-06 폐지했다(`00-목차-INDEX.md` 정정표) — 발행은 유지하되 노출 기대는 금지.
