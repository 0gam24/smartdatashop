# 웹사이트 개발 레퍼런스 라이브러리

본 폴더는 smartdatashop.kr 작업 시 참고하는 **문서 라이브러리**다 (2026-08-26 구 docs/ 트리 대체).

## 시작점

작업을 시작하기 전에 **반드시** [`docs/references/00-목차-INDEX.md`](references/00-목차-INDEX.md)를 먼저 읽는다.
이 목차가 260개 문서 전체의 진입점이다.

## 문서 우선순위 (충돌 시)

| 순위 | 폴더 | 역할 |
|---|---|---|
| 1 | `docs/references/G-구글-공식가이드/` | Google 관련 **모든 판단의 최종 근거** (174문서) |
| 1 | `docs/references/H-네이버-공식가이드/` | 네이버 관련 **모든 판단의 최종 근거** (55문서) |
| 2 | `docs/references/A~F/` | 실행 방법·프로젝트 규칙 요약 (31문서 — F에 스마트데이터샵 포스팅 구조 엔진 V4 포함) |
| 3 | `docs/references/_archive/` | 이력 참고용. **작업 근거로 쓰지 않는다** (구 google-seo-vibe-coding·구 references 01~07 보존) |

내부 요약(A~F)과 공식 문서(G/H)가 다르면 **항상 G/H가 맞다**. 요약본을 근거로 스펙을 단정하지 말고,
해당 주제의 공식 문서를 열어 확인한 뒤 답한다.

## 검색 규칙

- 특정 스키마·메타태그·정책을 물으면 → G/H에서 **직접 파일을 열어** 확인한다. 기억에 의존하지 않는다.
- Google과 네이버는 규칙이 다르다. 한국 대상 사이트는 **양쪽 다** 확인한다.
  (네이버 고유: `Yeti` 크롤러 · `meta keywords` · RSS 제출 · IndexNow)
- 성능·접근성·보안처럼 공식 문서에 없는 주제는 A~F를 근거로 삼는다.
