## 절대 금지

### AI가 만들어낸 통계는 발행 금지

## 동일 주제 재발행 — 롱테일 차별화 원칙 (2026-07-01 운영자 지시 — 영구)

> 이미 다룬 주제라도 *발행을 막지 말고*, **다른 롱테일 키워드 + 다른 검색의도 + 실질적으로 다른 본문**으로 신규 발행한다.

- **주제 결정 직전 기존 글 확인** — `grep -ril "<핵심키워드>" src/content/` 로 동일 주제 글 존재 여부 점검(불변).
- 기존 글이 있을 때 분기:
  - ✅ **다른 롱테일 각도가 가능하면 → 신규 발행.** 구체 롱키워드·구체 검색의도로 좁혀 쓴다. 예: "7월 머니 캘린더"(허브)가 이미 있으면 → "재산세 카드 무이자 할부 7월", "1인사업자 부가세 환급 받는 법 7월", "국민연금 상한 고소득자 7월 인상분 계산" 같은 *롱테일 스포크*. 허브 글과 **상호 내부링크**로 토픽 클러스터를 만든다.
  - ✅ **같은 검색의도·각도뿐이면 → 기존 글 보강**(신규 중복 회피, "기존 펄스 보강").
- 🔴 **AdSense 가드(불변)**: "다른 롱키워드"는 *검색의도가 실제로 달라야* 한다. 같은 의도를 단어만 바꾼 근접 중복은 cannibalization·scaled content 로 **여전히 금지**. 각 스포크도 골든 레퍼런스 깊이(공백 제외 3,000자+)·ADR 0006 4기준·원본 가치를 충족해야 한다.
- **차별화 자가 점검**: 신규 스포크의 (a) 타깃 롱키워드 (b) 핵심 검색의도 (c) 본문 H2 구성이 기존 글과 *겹치지 않는지* 발행 전 1줄로 확인. 셋 중 둘 이상 겹치면 신규 대신 보강.

## AI 문체 티 제거 룰 (2026-07-10 운영자 지시 — 영구)

> 제목·tldr·본문에서 AI 생성 티가 나는 패턴을 금지한다. 사람이 쓴 데이터 저널 문체를 유지한다.

- 🔴 **전각 대시(—) 금지 — 제목·tldr·본문 산문에서.** 제목은 "주제 2026 — 부제" 틀 대신 자연스러운 한국어 제목으로: 쉼표·조사·괄호 활용 (예: "교육비 세액공제 2026, 자녀 300만 대학 900만" / "퇴직 후 건강보험료 줄이는 임의계속가입"). 본문 삽입구는 쉼표·괄호·문장 분리로 대체.
- **고정 보일러플레이트 변주 의무**: "핵심은 세 가지입니다", "먼저 큰 그림입니다", "정리하면, ~입니다", "~한눈에" 같은 문형을 매 글 동일하게 반복하지 않는다. 글마다 도입·요약 문형을 다르게 쓴다 (스팸/AI 패턴 회피, 구글 scaled content 신호 차단).
- 허용: 각주 서지 표기(`[^N]: 기관, 「제목」 — URL`)와 frontmatter 외 코드·표 내부의 기호는 서지/데이터 형식이므로 예외.
- 기발행 글 소급 수정은 하지 않는다 (색인 보존). 신규 발행분부터 적용.

## 새 펄스 추가 시
1. 파일명: `YYYY-MM-DD-slug.mdx` (slug는 영어 소문자/하이픈)
2. publishedAt: ISO 8601 + KST 시간대 (예: `2026-05-05T07:32:00+09:00`)
3. category: 5개 enum 중 1개 (`policy`/`tax-finance`/`market`/`stats`/`ai-tech`)
4. tldr: 목표 90~150자(상한 200자) 요약 — **"X 는 Y 다" 정의 문장 포함** (LLM 인용 친화)
5. sources: 최소 1개 (`url` 권장 — Dataset LD 자동 발행 조건). **3개+ 시 GEO·SEO 가산 신호**.
6. tags: persona/dataType/action 중 해당하는 것
7. body: **공백 제외 3,000자+ (중복 없는 분량 — V4-6)**. 구조는 V4 구조 엔진 따름
8. (선택) `chartData`: Reuters/Bloomberg 스타일 OG 차트 오버레이 — `{ type, values, label, unit? }`
9. (선택) `coverImage`: 1200×630 16:9 — 없으면 동적 OG v2 (Satori) 자동 사용

### 포스팅 구조 엔진 V4 (2026-08-26 운영자 지시 — GOOGLE_CONTENT_PROMPT V4.0 적용)

> **목적: 구글 scaled content(AI 대량 생성) 판정 회피.** 문장 변주(2026-07-10 룰)만으로는 부족하다 — 최근 발행분 분석 결과 문서 골격이 10/10 동일했다. **문서 구조 자체가 검색의도에 따라 글마다 달라야 한다.**
>
> 적용 범위: *본문 구조만* 본 절로 전면 교체. 주제·키워드 선정 운영(위 롱테일 차별화 절 + 루트 CLAUDE.md 발행 방침: 기본 3편/상한 5편·질 우선)은 기존 그대로.
> 폐기: "골든 레퍼런스 구조 복제" 지시, 구 포스팅 청사진(`docs/posting-blueprint.md`)의 골격 대입 지시 — 구조에 관해서는 **본 절이 청사진을 대체**한다 (청사진의 발굴·주제 선정 파트는 유효). 골든 레퍼런스(2026-05-28-voice-phishing)는 이제 *깊이·검증 품질*의 기준으로만 남고 **구조 모델이 아니다**.

**V4-1. 구조 선택 — 검색의도별 TYPE (모든 글 동일 템플릿 금지)**

작성 전 이 글의 PRIMARY INTENT(핵심 검색 질문)를 정하고 TYPE을 고른다 (조합 가능):

- **A 문제해결형** / **B 제도설명형** / **C 비교분석형** / **D 계산형** / **E 사례분석형** / **F 변경사항형** / **G 산업·기업 심층형** / **H 투자테마형**

TYPE별 자연 골격 예 (강제 골격 아님 — 검색자 질문이 해결되는 순서로):
- B 제도: 핵심 조건 → 대상 → 금액 → 신청 → 예외 → 실무 마찰
- C 비교: 핵심 차이 → 비교표 → 항목별 분석 → 상황별 판단
- D 계산: 기준 → 산식 → 사례 → 결과 해석
- F 변경: 무엇이 달라졌나 → 이전과 차이 → 적용 시점 → 영향받는 조건

- ☐ **H2는 실제 질문을 해결하는 것만** — 개수 채우기용 섹션 금지. H2 개수 하한(6개+) 폐지, 검색의도 해결에 필요한 만큼만.
- ☐ **H2 골격이 기존 발행 글과 겹치지 않게 재구성** — 자동 검출은 백스톱일 뿐: verify:structure 는 헤딩 시퀀스 *완전 동일*만 fail, 역할 슬롯 시퀀스 동일은 warn. **골격 다양화의 실질 책임은 작성자**다 (헤딩 문구만 바꾼 동일 골격은 자동으로 안 잡힌다).
- ☐ 도입 첫 화면: 검색자가 가장 궁금한 답(핵심 수치·조건·판단 기준)을 빠르게. 단 "이 글에서는 ~을 정리한다" 류 고정 도입 문형 매 글 반복 금지.
- ☐ 각 H2 첫 문단 = 그 섹션의 즉답 (유지 — AEO)
- ☐ 인용 단락(`> 원문` + `[^N]`) — 정책 펄스 의무 (유지)
- ☐ footnote `[^N]` 본문 자연 분포 (유지 — ADR 0006)

**V4-2. Information Gain — 독창적 가치 2개+ 의무**

> 기존 "페르소나 매트릭스 의무 + 국제 비교 의무 + 표 1개 의무" 일률 강제는 폐기 — 아래 메뉴의 *선택지*로 전환. 주제에 맞는 것을 2개 이상.

① 직접 계산("편집자 계산: 식" 명시) ② 기존 문서에 없는 비교 기준 ③ 공개 사실 기반 독립 해석 ④ 명확한 기준의 분류 ⑤ 시간 흐름 타임라인 ⑥ 독자 판단 기준 제공 ⑦ 조건별 시나리오 ⑧ 실무 마찰 지점 분석 ⑨ 교차 출처 종합 ⑩ 수치의 의미 해석 ⑪ 검색 결과에 없는 후속 질문 답변 ⑫ 페르소나별 영향

- ☐ 정보가 부족하면 **분량을 늘리지 말고 리서치를 추가**한다. 리서치로도 못 채우면 그날 편수를 줄인다(발행 보류) — 루트 CLAUDE.md AdSense 정책과 동일.
- ☐ "상황에 따라 다르다" / "공식 홈페이지를 확인하라" 를 정보 대체물로 쓰지 않는다 — 쓸 경우 구체적 확인 경로·실데이터 동반.
- ☐ 표는 비교·데이터 구조화가 필요할 때만 (의무 아님). 사례형·타임라인형엔 표가 부적합할 수 있다.

**V4-3. FACT / INTERPRETATION / ESTIMATION / EXAMPLE 구분**

- FACT: ADR 0006 4기준 그대로 (footnote 페어링 + 발표일 명시 + deep link + 검증불가 격리).
- INTERPRETATION: "편집자 해석:" 라벨 / ESTIMATION: "편집자 추정(가정: ~):" 라벨 / EXAMPLE: "가상 사례" 명시.
- 추정을 사실처럼, 가상 사례를 실경험처럼 쓰지 않는다. 1인칭 경험("직접 해보니/신청해보니") 절대 금지.
- 라벨링된 해석·추정 레이어는 Information Gain 의 핵심 — 위축시키지 말 것. 단 FACT 검증(ADR 0006)은 불변.

**V4-4. 중복 제거 엔진 (scaled content 신호 차단 핵심)**

- ☐ **체크리스트성 블록(체크리스트/체크포인트/확인 포인트/확인사항/점검/핵심 정리) 문서 전체 최대 1개.** 기존 "독자 체크리스트 + 유형별 확인 포인트" 이중 배치 표준 폐기.
- ☐ **FAQ는 조건부** — 본문이 답하지 않은 실제 후속 질문·예외·경계 조건·흔한 오해만. 본문 재서술 Q&A 금지. **새 정보가 없으면 FAQ 섹션 삭제.** "Q1. X는 무엇인가요?" 고정 정의 문형 금지(정의는 tldr·도입이 담당). 매 글 3개 고정 금지 — 개수는 실제 질문 수에 따라.
- ☐ **마무리 섹션 = 본문 재요약 금지.** "~가 주는 큰 그림" 류 재요약 슬롯 폐기. 마무리는 독자의 다음 행동: 무엇을 추가 확인할지, 어떤 공식 자료(고시·통계 DB·DART)를 볼지, 어떤 조건에서 판단이 달라지는지. 1~2문단이면 충분.
- ☐ **표 직후 해설 = 표에 없는 함의·판단만.** 표 행 수치를 산문으로 재나열 금지. "표를 풀어 보면" / "표에서 보듯" 개시 문형 금지.
- ☐ 동일 핵심 수치의 본문 반복은 최소화 — 제목→tldr→도입→본문→표→FAQ 에 같은 수치 5~7회 반복(기존 패턴) 금지.
- ☐ **문단 삭제 테스트**: 삭제해도 독자가 새 정보를 잃지 않는 문단은 삭제·통합.

**V4-5. 표현 룰 (AI 문체 티 제거 룰 확장)**

- ☐ 산문 "→" 화살표 단계형 표현 **글 전체 최대 1회** (표 셀 0회 기존 룰 유지, 각주 서지·코드 예외).
- ☐ 습관 표현 금지: "첫째,/둘째,/셋째," 열거, "결론적으로", "정리하면,", "다시 말해", "쉽게 말하면", "표에서 보듯", "표를 풀어 보면" — 정보 전달에 꼭 필요한 단발 사용 외 금지.
- ☐ 전각 대시(—) 금지 + 고정 보일러플레이트 변주 의무: 위 "AI 문체 티 제거 룰" 절 그대로.

**V4-6. 분량 — 패딩 금지 원칙으로 재정의**

- ☐ 공백 제외 3,000자+ 기준 유지 (AdSense 재건 정책) — 단 **중복 없는 3,000자**.
- ☐ 기존 "자수 미달 시 §배경·§시사점 보강" 지시 폐기 → 미달 시 리서치 추가, 그래도 부족하면 발행 보류. 글자 수를 채우기 위한 일반론·재요약 문단 생성 금지.

**V4-7. 금융·관련주 콘텐츠 추가 룰 (신설)**

- ☐ 관련주 언급 시 기업별 연결 근거 4단계 명시: **[직접 관련] / [간접 관련] / [시장 테마상 연관] / [관련성 낮음]**. "테마 포함 = 수혜 확정" 논리 금지.
- ☐ 하드 데이터(매출·영업이익·관련 사업 매출 비중·수주잔고·CAPA·현금흐름 등) 1개+ 분석 없이 종목 나열 금지.
- ☐ 리스크 병기 의무: 과열·실적 괴리·낮은 매출 비중·CB/BW 희석·유상증자·고객 집중 등 해당 항목.
- ☐ 수익 보장·상승 확정·목표주가 생성 절대 금지 (확인 불가 공시번호·전망치 포함 — ADR 0006 연장).

**V4-8. LD 자동 발행과의 관계**

- FAQPage/HowTo LD 는 해당 블록이 *실제 가치가 있어 존재할 때만* 자동 발행되면 충분하다. **LD 트리거를 위해 FAQ·체크리스트를 억지로 넣지 않는다** — LD 발행 감소를 감수한다 (실제 페이지와 불일치하는 가짜 구조가 더 위험).

**V4-9. 자동 검증**

- `npm run verify:structure` (`scripts/verify-post-structure.mjs`) 가 **2026-08-27 이후 발행분**(publishedAt 기준, 채택일 8/26 당일 기발행 3편 면제)의 구조 위반을 검사: 체크리스트성 블록 2개+, 산문 "→" 2회+, 산문 전각 대시, FAQ 고정 정의 문형, 금지 문형, H2 시퀀스 완전 복제(fail)·슬롯 시퀀스 유사(warn). `verify` / `verify:strict` 체인 + build-check CI 편입. writer.mjs 자동 발행 경로는 발행 직전 인라인으로 동일 검사.
- 기발행 글(컷오프 이전)은 소급 수정 금지(색인 보존) — 검사 제외.
- 게이트는 백스톱이다 — 통과가 곧 "구조 다양화 충분"을 뜻하지 않는다. 발행 전 직전 5편의 H2 골격과 눈으로 대조하라.
